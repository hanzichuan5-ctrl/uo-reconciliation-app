# 月度工作台

本机 Python + SQLite + FastAPI 服务，配轻量 HTML/JavaScript 界面。双击上一级的“打开月度工作台.command”，会启动服务并打开 http://127.0.0.1:8770。

## 日常使用

在“本月资料”中选择处理月份、用途和主体，上传原始Excel。发票、银行流水按表内日期检查月份；系统导出、申请资料独立选择；回款底稿由使用者明确选择。点击“重新检查”读取有效来源，重复导入相同文件不会增加记录。

收入侧从实际发票出发，按申请和备注找渠道、账期及游戏，再核对系统开票金额和收入同步状态。只有金额一致、记录不重复、证据可定位的事项才进入待操作。缺少月份的同额记录列为候选，人工确认后才能形成对应关系。本地“我已在UO完成”只保存操作确认，系统状态仍来自导出。

回款侧只使用银行流水和所选底稿的“回款”页。已在本月底稿出现且与银行逐笔一致的来款保留；新来款按摘要提出建议或待核实，由使用者逐笔确认。腾讯FPP不作为未来月份自动纳入规则。所有输出都生成副本，不写原文件。

## 文件与状态

- `monthly-state/workbench.sqlite3`：月份、来源、确认、输出版本及操作记录。
- `monthly-state/sources`：按内容哈希保存的已允许来源副本。
- 项目 `outputs/01a09463-3c83-7201-9d6d-69bf2672c926-monthly`：生成的Excel及验证记录。
- 原始文件、来源副本、业务记录三者分开；换浏览器不丢失处理状态。

初始资料只从原始归档中恢复指定发票、申请与7月流水，另读取项目中的系统表、8月流水和用户最后检查的精确8月底稿。不读取已排除业务表，不导入旧网页数据、旧匹配规则、旧拆分结果。7月与8月分别展示，不因文件放在一起而混合月份。

## 维护

主处理模块 `core.py`，Excel输出 `exporter.py`、`export.mjs`，API `server.py`，页面 `web/`。来源与规则变化时需要增加解析器和有区分力的测试。表头变化会显式报错，不能静默错读。工作台不会自动访问UO或执行收入同步。

已有模板仅在“回款”部分作定点更新。扩容时移动该页行、合并区和小计，并核对其他包内容保持一致。若回款页自身有尚未适配的关联表格或绘图，扩容会停止并提示具体原因；不重建整本工作簿。

运行：`.venv/bin/python -m uvicorn monthly.server:app --host 127.0.0.1 --port 8770`

测试：`.venv/bin/python -m pytest monthly/tests -q`。测试使用临时SQLite副本；合成记录只存在临时输出中，不进入实际工作台。

Excel输出依赖本机bundled Node的 `@oai/artifact-tool`；Python库在项目 `.venv`。迁移电脑时需重新建立运行环境并配置 `exporter.py` 中的 Node路径。
